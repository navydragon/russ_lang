# Spec Delta

## Purpose

Предоставлять администраторам russ_lang единый интерфейс управления группами и студентами с проверяемым импортом из Excel и отображением результата операций основного портала.

## ADDED Requirements

### Requirement: Доступ к управлению
Система SHALL разрешать операции управления и импорт только авторизованным пользователям с is_staff, проверяя права на сервере.

#### Scenario: Пользователь без прав
- **WHEN** пользователь без is_staff отправляет запрос создания, изменения, удаления или импорта
- **THEN** система отклоняет запрос и не изменяет данные обеих систем

### Requirement: Управление группами
Система SHALL поддерживать создание и редактирование группы по общему уникальному code с сохранением названия и локальных кураторов; успешное сообщение SHALL означать подтверждённое изменение портала и локальных данных.

#### Scenario: Создание группы
- **WHEN** администратор сохраняет валидную группу
- **THEN** группа с указанным code существует в обеих системах, а локальная запись связана с ID портала

#### Scenario: Изменение названия
- **WHEN** администратор меняет название группы
- **THEN** обе системы сохраняют новое название для той же группы без создания дубля

### Requirement: Создание и редактирование студента
Система SHALL предоставлять модалки создания и редактирования студента внутри группы с ФИО, почтой и общим ключом code = login. Ключ существующей записи SHALL оставаться неизменным в этих формах.

#### Scenario: Новый студент
- **WHEN** администратор сохраняет валидного нового студента через модалку
- **THEN** пользователь создаётся или находится на портале и отображается в выбранной группе russ_lang с подтверждённым членством

#### Scenario: Редактирование
- **WHEN** администратор меняет ФИО или почту студента
- **THEN** обе системы обновляют эти поля существующей записи, сохраняя её ключ, пароль и результаты

### Requirement: Импорт в выбранную группу
Система SHALL предоставлять скачиваемый XLSX-шаблон и предварительную проверку файла до записи. Импорт SHALL использовать выбранную в интерфейсе группу и ключ code = login, сохраняя строковые коды и ведущие нули.

#### Scenario: Валидный файл
- **WHEN** администратор загружает заполненный шаблон
- **THEN** система показывает строки для создания или обновления и выполняет импорт только после подтверждения

#### Scenario: Ошибки файла
- **WHEN** файл содержит отсутствующие обязательные заголовки, повторяющиеся коды, несовпадающие code и login или невалидные строки
- **THEN** система показывает причины с номерами строк и запрещает запуск импорта до исправления ошибок без записей в обе системы

#### Scenario: Повторный импорт
- **WHEN** администратор повторно импортирует того же студента
- **THEN** ФИО и почта обновляются, пароль сохраняется, пользователь и членство не дублируются

### Requirement: Результат частичного импорта
Система SHALL показывать подтверждённый результат каждой строки: создано, обновлено, без изменений или ошибка. При сбое выполнения уже подтверждённые строки SHALL сохраняться, а повтор файла SHALL быть безопасным.

#### Scenario: Сбой портала на части строк
- **WHEN** после успешных строк портал отклоняет следующую строку или перестаёт отвечать
- **THEN** интерфейс показывает успешные строки и ошибку либо неопределённый результат остальных, не объявляя весь импорт успешным

### Requirement: Удаление членства и пустой группы
Система SHALL удалять студента только из выбранной группы в обеих системах, сохраняя пользователя и результаты. Удаление группы SHALL разрешаться только при отсутствии членов на портале и студентов локально.

#### Scenario: Исключение студента
- **WHEN** администратор подтверждает удаление студента из группы
- **THEN** членство снимается в обеих системах, пользователь, локальная запись студента и результаты сохраняются

#### Scenario: Непустая группа
- **WHEN** администратор пытается удалить группу с членами хотя бы в одной системе
- **THEN** система отклоняет удаление и сообщает причину
