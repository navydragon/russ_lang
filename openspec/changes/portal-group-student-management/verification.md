## Сквозная проверка

`scripts/check_roster_websoft.py` выполнил запросы Django Client через настоящий сетевой адаптер к работающему локальному WebSoft: создание группы, удалённая запись с имитацией потерянного ответа, безопасный повтор, создание/редактирование студента, предпросмотр и выполнение одного XLSX дважды, исключение и удаление пустой группы.

Для этой проверки использована отдельная тестовая БД Django и временная учётная запись портала. Только тестовый opener заменяет известный тестовый HTTPS-хост на HTTP loopback; рабочий адаптер принимает исключительно HTTPS и не следует перенаправлениям.

## Ограничения готовности

- Полный `manage.py check` подтверждённо останавливается на существующих маркерах stash-конфликта в `api/reading_check.py:225`. Второй прежний конфликт остаётся в `tasks/api-config.js`. Они не изменялись этой реализацией и требуют отдельного разрешения до обычного запуска приложения.
- `graphify update .` запущен, но launcher ссылается на отсутствующий Python311; граф не обновлён.
- Для рабочего API нужны токен выделенной учётной записи в `.env` Django и её ID в локальной конфигурации WebSoft; инструкция — students/ROSTER.md и api/docs/russian-roster.md. Боевой https://api.emiit.ru в ходе проверки не изменялся и не проверялся.
- Проверки UI выполнены через Django Client и рендеринг шаблонов, без автоматизации браузера.
- Блокировки рассчитаны на один экземпляр WebSoft и один хост Django. Развёртывание кластера требует общей блокировки.
