# Design

## Context

`courses/test_launcher.py` строит карточки из `TASK_CATALOG` и показывает их только при `DEBUG`. Тестовые результаты принадлежат отдельному ученику и не отражают проверку автором.

## Goals / Non-Goals

**Goals:** общая отметка в базе по устойчивому коду задания; достоверная дата последней известной правки; доступность всем посетителям существующей страницы.

**Non-Goals:** идентификация автора отметки, история действий, изменение результатов или открытие страницы в production при `DEBUG=False`.

## Decisions

Хранить подтверждение отдельной моделью с уникальным кодом из каталога, не связывая его с тестовым учеником или объектом задания в конкретном курсе. Хранить даты правок в явном реестре по коду задания, обновляемом вместе с правками и итоговым перечнем; при отсутствии достоверной даты не создавать запись. При последующей правке обновлять дату; автоматическое снятие подтверждения не вводится без отдельного требования. Использовать POST с CSRF-защитой, проверкой кода по каталогу и тем же ограничением `DEBUG`, что у страницы. При ошибке показать сообщение и восстановить фактическое состояние; повторные запросы должны сохранять заданное состояние идемпотентно.

## Risks / Trade-offs

- [Локальные базы разных серверов] → отметки общие в пределах одной базы, не синхронизируются между независимыми установками.
- [Ручной реестр устареет] → обновлять дату и итоговый перечень при каждой правке, покрыть известные коды проверкой.
- [Одновременные изменения] → последняя успешно сохранённая запись является текущим состоянием.

## Migration Plan

Применить миграцию до запуска обновлённой страницы; при откате кода сохранённые отметки остаются в базе и не мешают прежней версии.
