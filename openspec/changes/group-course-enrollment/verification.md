## Локальный WebSoft

- Новый защищённый action ensure_course_assignments проверен через `http://127.0.0.1/_wt/russian_language/action/ensure_course_assignments` с отдельной учётной записью интеграции.
- Неверные/отсутствующие реквизиты: 401; действительная запись вне allowlist и студент без членства: 403. Некорректные ID (JSON-число, ноль, int64 overflow, отсутствующий курс в наборе) отклоняются до выдачи назначений.
- Два новых назначения создаются; повтор возвращает unchanged. После штатного завершения тестового курса повтор не создаёт active_learning: остаётся одна архивная learning с баллом 87. Назначений семестров нет.
- 12 запросов с параллельностью 6 для одной пары создали ровно одну active_learning; все успешные ответы содержали один learning_id.
- Выявлена особенность штатного activate_course_to_person: при новом назначении возвращается документ, при существующем — ID. Обработчик поддерживает оба варианта; это проверено реальным вызовом и тестом.
- `node tests/russian_roster.test.cjs`: проверки исходного CRUD, ID назначения, завершённого обучения, результата создания, дублей ID и частичного ответа — PASS. В тестовом VM адаптируется только синтаксис for-in WebSoft и EvalCs; конкурентная сериализация отдельно проверена реальным сервером.

## Сквозная и браузерная проверки

- `scripts/check_group_course_websoft.py` использовал отдельную тестовую БД Django, настоящий серверный адаптер и только собственные тестовые коды на локальном WebSoft.
- Группа из 20 студентов и два курса: потерян ответ после удалённого назначения, локальный выбор сохранил предыдущий набор, повтор завершил выдачу. Замеры повторного полного сохранения: 11.375 и 14.344 секунды. Синхронный сценарий на больших группах может требовать повторов при инфраструктурном таймауте; фоновая очередь в этот change не входит.
- Проверены два импорта одного XLSX без дублей, исключение с сохранением локальных результатов и удаление курса из выбора без отзыва. Студент, созданный после удаления второго курса из выбора, получил только первый: active counts 1 и 0. Ранее зачисленный сохранил второй курс; завершённый первый сохранил балл 87.
- В браузере: создание группы с одним курсом, создание студента через модалку, выбор двух курсов в редактировании группы и автоматическая выдача второго. Аудит WebSoft подтвердил по одному назначению каждого курса. В узкой панели поправлено расположение заголовка и кнопок.
- Скриншот подтверждения: `.test-venv/course-enrollment-ui.png`.
- После проверки удалены только собственные тестовые данные: две группы, два тестовых курса, 22 тестовых пользователя, их обучения и временная запись сотрудника Django. Существующие пользователи, курс и результаты не затронуты.
- Временный исполняемый enrollment_fixture.html удалён. Неисполняемый исходник для воспроизведения сохранён в API/tests/enrollment_fixture.html.txt; он требует авторизацию интеграции и оперирует фиксированными тестовыми кодами. Использовать только на локальном стенде.

## Готовность и ограничения

- Локальное приложение оставлено на `http://127.0.0.1:8888`, настройка API — `http://127.0.0.1/_wt`. Поддержка HTTP ограничена loopback; внешний адрес требует HTTPS.
- Перед production нужен отдельный деплой нового action API, затем миграции и клиент. Откат не должен удалять ранее выданные обучения.
- Изменение ID курса в каталоге не запускает фоновую массовую выдачу; для доназначения нужно сохранить группу или студента.
- `graphify update .` вызван, но launcher по-прежнему ссылается на отсутствующий Python311. Граф не обновлён.
