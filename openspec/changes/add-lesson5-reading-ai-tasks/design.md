# Design

## Context

См. `proposal.md` и `specs/lesson5-reading-tasks/spec.md`. В проекте уже есть общий реестр `READING_TASKS`, API проверки и сохранения попыток, страницы чтения урока 4 с оригинальными записями и страницы урока 7 с записью без исходного аудио. Новый формат и отдельный backend для чтения не нужны.

## Goals / Non-Goals

**Goals:**

- Добавить пять независимых страниц чтения, каждая со своим текстом, лимитом, кодом и результатом.
- Использовать существующий механизм распознавания, оценки полноты и пауз.
- Дать студенту прослушать эталонный образец перед собственной записью.

**Non-Goals:**

- Не реализовывать остальные одиннадцать карточек урока 5.
- Не добавлять отдельную акустическую модель для ударения, интонации или чёткости окончаний.
- Не менять общий формат проверки или хранения попыток.

## Decisions

1. **Переиспользовать общий механизм чтения.** Для каждого задания добавить запись в `READING_TASKS` с эталонным текстом и лимитом. Страницы используют имеющийся сценарий записи, отправки, отображения распознанного текста и сохранения результата. Это сохраняет одинаковое поведение с уже работающими заданиями чтения.

2. **Назначить независимые идентификаторы по порядку этих пяти новых страниц.** Использовать task ID `lesson5_classroom_reading`, `lesson5_juan_carlos_reading`, `lesson5_family_reading`, `lesson5_parrot_reading`, `lesson5_thomas_edward_reading` и коды `AI_5_1`–`AI_5_5` соответственно. Лимиты: 120 секунд для `AI_5_1`, 180 секунд для остальных.

3. **Хранить полный эталон текста в конфигурации проверки и показывать тот же источник на странице.** Перенести тексты без редакторского пересказа из `tasks/lesson5/SOURCE_MATERIALS.md`; для согласованности страница и серверная проверка должны опираться на одну версию текста.

4. **Подготовить локальный аудиообразец для каждого текста.** Сначала использовать оригинальную запись курса, если её удаётся получить в пригодном локальном формате. Если нет — создать `reference.wav` через существующий Yandex SpeechKit pipeline. На странице обозначать происхождение образца точно; не называть синтезированный голос оригинальной записью диктора.

5. **Сохранить отдельные попытки по каждому коду.** Зарегистрировать задания в каталоге и валидации кода, чтобы результат одной страницы не попадал под другой `AI_5_*`. Оценка остаётся 100-балльной с зачётом от 60; объяснить, что распознанный текст не позволяет надёжно проверить ударение, интонацию и ясность окончаний.

## Risks / Trade-offs

- [Распознавание ошибается на именах и окончаниях] → использовать существующее сравнение текста и описывать результат как оценку полноты и пауз, а спорное произношение не выдавать за проверенное.
- [Синтезированная озвучка может отличаться от записи курса] → предпочесть оригинальный файл при его доступности; для синтеза явно указывать Yandex SpeechKit и прослушать готовый образец при подготовке страницы.
- [Коды могут смешать попытки, если task ID и код не совпадут] → задать однозначное соответствие пяти task ID кодам `AI_5_1`–`AI_5_5` в API и каталоге.

## Migration Plan

Новых полей или преобразования существующих попыток не требуется. Добавить пять новых записей каталога; повторный локальный seed должен создать недостающие записи заданий, не затрагивая имеющиеся попытки. Откат — удалить новые страницы и записи каталога/реестра, не удаляя ученические попытки.
