# Группы и студенты основного портала

## Курсы WebSoft

Курс в Django содержит «ID WebSoft» (редактируется в Django admin). Основной курс «Русский язык для иностранных студентов» связан с `7221015156608859696`; тестовый ИИ-курс автоматически не связывается. Аддитивная миграция сохраняет локальные ID и результаты и не назначает курсы историческим группам. Команда `sync_russian_course --apply` поддерживает эту привязку при создании и повторной синхронизации.

При создании или редактировании группы выберите один или несколько курсов. Пустой выбор разрешён: тогда новых назначений не будет. Курс без ID WebSoft сначала нужно связать в каталоге через Django admin. XLSX-шаблон студентов прежний — курсы определяются группой.

Новый или импортированный студент получает текущие курсы группы. При сохранении группы выбранные курсы доназначаются всем её текущим студентам. Повторное сохранение проверяет весь набор, поэтому восстанавливает недостающие назначения после сбоя. Существующие активные и завершённые обучения, баллы и прогресс сохраняются; семестры и уведомления не создаются.

Удаление курса из списка группы не отзывает выданные назначения. Будущие студенты получают только текущий выбор. При исключении студента из группы его курсы и результаты также остаются.

При частичной ошибке сообщение указывает студента и курсы. Часть назначений WebSoft могла выполниться, но локальный список группы остаётся последним полностью подтверждённым. Повторите то же сохранение — уже выданные назначения будут использованы повторно. Изменение ID курса в каталоге само по себе не запускает массовую выдачу: после него сохраните нужные группы заново.

Развёртывайте новый action `ensure_course_assignments` на целевом API до обновления клиента, затем применяйте миграции и перезапускайте Django. Для отката сохраните поля и уже выданные обучения, вернув прежний клиент. Локальная проверка не означает, что production API уже обновлён.

Управление доступно сотрудникам с `is_staff`. На странице управления создайте группу с уникальным кодом; код после создания не меняется. Название и кураторы редактируются обычной формой. Кураторы хранятся локально.

Откройте студентов группы. Кнопки «Добавить студента» и «Редактировать» открывают модалки. Код студента равен логину портала и остаётся неизменным. Создание использует существующего пользователя с этим ключом или создаёт нового. ФИО и почта обновляются, существующий пароль сохраняется. Семестры и дисциплины не назначаются.

## Импорт

1. Нажмите «Импорт из Excel» и скачайте шаблон этой страницы. Он отличается от старого консольного многогруппового шаблона: группа уже выбрана, колонки кураторов не нужны.
2. Заполните Фамилия, Имя, Отчество, Почта, code, login, password. Фамилия, Имя, code и login обязательны; code и login должны совпадать и быть текстовыми значениями. Почта, отчество и пароль необязательны. Формулы запрещены. Максимум 1000 строк и 5 МБ.
3. Нажмите «Проверить файл». На этом шаге записи не изменяются. Исправьте ошибки строк и повторите проверку.
4. Подтвердите импорт. Файл обрабатывается порциями до 25 строк, результаты показываются отдельно. Не меняйте файл во время выполнения.
5. При сбое проверьте результаты и повторите тот же файл. Уже выполненные операции не создадут дублей. «Результат неизвестен» означает потерянный ответ, а не отсутствие записи на портале.

Предпросмотр определяет предполагаемое действие по локальным данным; окончательный результат создания/обновления определяется порталом. Для существующего пользователя password из файла игнорируется. Пароли не выводятся и не сохраняются в локальном профиле. Если пароль нового пользователя пуст, генерируется случайный; выдача реквизитов и отправка писем этой функцией не выполняются.

Студента из другой локальной группы сначала исключите из прежней группы. «Удалить из группы» снимает только членство, сохраняя пользователя и результаты в обеих системах. Другие членства портала не изменяются. Удалить можно только пустую группу.

## Подключение

В `.env` Django задайте `PORTAL_ROSTER_URL=https://api.emiit.ru/_wt`, `PORTAL_ROSTER_TOKEN` (Base64 от `login:password` выделенной учётной записи) и при необходимости `PORTAL_ROSTER_TIMEOUT=10`. Значения не добавляйте в Git. Настройка из `.env` загружается при старте процесса, поэтому после изменения нужен перезапуск приложения.

На WebSoft настройте разрешённый ID этой учётной записи согласно `api/docs/russian-roster.md`. Без токена или разрешённой записи операции записи завершаются ошибкой, не переходя к локальной записи. Сетевые перенаправления запрещены, чтобы не пересылать авторизацию на другой адрес. Обмен — только HTTPS.

Для локальной разработки установите `PORTAL_ROSTER_URL=http://127.0.0.1/_wt`. HTTP разрешён только для loopback (`127.0.0.1`, `localhost`, `::1`), внешние адреса требуют HTTPS. Запуск проверенного окружения: `.test-venv\Scripts\python.exe manage.py runserver 127.0.0.1:8888 --noreload`; страница управления — `http://127.0.0.1:8888/groups/`.

## Развёртывание и откат

1. Разверните новые маршруты API и `libs/russian_roster.js`; настройте учётную запись интеграции. Проверьте её полномочия на тестовых кодах.
2. В russ_lang выполните `python manage.py migrate`, затем настройте переменные окружения и перезапустите Django. Миграция добавляет nullable ID портала и email без массовой синхронизации старых записей.
3. Проверьте тестовую группу, модалку, повтор импорта, исключение и удаление пустой группы. Старые группы получают связь с порталом при первой операции.
4. При откате сначала отключите новые операции управления. Верните прежнее приложение, сохранив аддитивные поля БД и созданные данные портала. Автоматически удалять пользователей или их результаты нельзя.

Локальная сериализация использует блокировку ОС между процессами одного хоста. WebSoft выполняет короткие операции поиска/записи внутри штатного `EvalCs`. Текущий вариант рассчитан на один экземпляр WebSoft и один хост Django; для кластера нужна общая блокировка на уровне БД. Если процесс завершается, блокировка ОС освобождается автоматически.

## Проверка

`python manage.py test students.test_roster --settings=config.roster_test_settings`

Конфликты stash в `api/reading_check.py` и `tasks/api-config.js` разрешены в ходе локальной разработки с сохранением исправленной расшифровки и параметров пауз. Общий `manage.py check` проходит. Проверка интеграции и чтения: `python manage.py test students.test_roster api.tests`.
